# inkbrief

**多张图 + 多段文案 → 一支带配音和手写字幕的手绘讲解视频。** 全在浏览器里跑：图片不上传、文案不上传、配音也在本地合成。导出一个 MP4，直接能发。

在线用：<https://longguanhong0755.github.io/inkbrief/>

---

## 成品长什么样

贴 8 张图、粘 8 段稿子，逐段配上音，得到一个 8 屏的视频：

- 第 1 屏，配音先响，笔尖从左上落下，把第 1 张图一点点画出来；字幕在下方按念到的节奏逐字浮现。
- 这一段说完，画面硬切到第 2 屏，第 2 张图开始画，第 2 段配音接上。
- 一屏接一屏，直到最后一段念完，定格结束。
- 导出 1920×1080（或竖屏 1080×1920）MP4，30fps，音轨烧在里面。

## 三步

**1. 图片** — 拖进左侧，或点选，可一次多选。顺序就是出场顺序。

**2. 文案与配音** — 把整篇稿子粘进上面的框，点「按空行分段」（没有空行时会按句号切）。
每段卡片上有三样东西：

| 位置 | 作用 |
|---|---|
| `图 N` 按钮 | 点一下换成下一张图 |
| `配音` 按钮 | 用本地语音引擎念这一段；念完显示实际秒数 |
| 时长滑块 | 拖它改这一屏的长度，配音会自动变速去匹配 |

**3. 预览与导出** — 点「生成」跑笔触分析（每张图几秒到几十秒），然后在右侧播放、拖进度、点场景标签跳转，最后「导出视频」。

## 时长怎么定（这是这个工具的核心规则）

一屏有四个时间互相拉扯，顺序是：

```
手动拖过滑块   → 用你拖的值（配音跟着变速，不被截断）
没拖过，有配音 → 用配音的真实长度
没拖过没配音   → 按字数估（每字 0.24 秒）
```

**拖动 = 给配音变速，不是砍掉配音。** 用的是 WSOLA 变速不变调：拖到 0.7× 声音会变慢但音高不变，拖到 1.5× 会变快，不会变成花栗鼠。

改文案会让这一段已有的配音失效（标黄「文案改过，需重配」），因为旧配音念的是旧文字。

## 配音是怎么来的

用 **Piper 中文模型（huayan x_low，fp16 量化到 10.1MB）+ onnxruntime-web** 在浏览器里直接推理，不发一个字节到服务器。

两个音色其实是**同一个说话人模型的两组 VITS 参数**（语速 / 起伏 / 音素时长抖动）：

| 音色 | 听感 |
|---|---|
| 温柔女声 | 语速偏慢（length_scale 1.12），起伏柔和 |
| 利落女声 | 语速偏快（0.94），起伏明显 |

音素化不用 espeak 运行时（那是 24MB 的 GPL 依赖），而是**离线用 espeak 生成「拼音+声调 → 音素」映射表**（1286 条，27KB），运行时用 pinyin-pro 判多音字再查表。所以整个前端只有 MIT/Apache 依赖。

## 导出

| 项 | 值 |
|---|---|
| 容器 | MP4（H.264 + AAC） |
| 分辨率 | 1920×1080 或 1080×1920，可勾「双画幅」一次出两个文件 |
| 帧率 | 30fps 固定 |
| 音轨 | 48kHz 单声道，各段按时间轴拼好，配音长度与画面严格对齐 |

导出走 **WebCodecs 离线编码**：逐帧把画面喂给硬件编码器，不受墙钟限制。
所以慢机器只是多花点 CPU 时间，**不会掉帧、不会音画错位**（MediaRecorder 实时录制就会）。
实测 2.4 秒的片子 1.1 秒编码完。

浏览器没有 WebCodecs 时退回 `MediaRecorder` 实时录制（兼容性好，但慢机只掉帧）。

## 交互怎么用

这一版把交互补齐了，用起来是这么回事：

| 想干什么 | 怎么做 |
|---|---|
| 配图 | 从左栏把图**拖到段卡上**；一屏能放多张图，每张有权重 |
| 看整片结构 | 底部**时间轴**，一块是一屏，能拖能改 |
| 细调某一屏 | 点段卡 → 右侧**场景设置栏**改画面 / 字幕 / 时间 |
| 改错了 | `Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做（连打 5 个字只算一步） |
| 配音 | 段卡上「配音」，或「批量配音」一次配完 |
| 看进度 | 底部**队列面板**：跑到第几张、哪张失败、失败的能单独重试 |
| 出片 | 「导出视频」，可选「双画幅」一次出横屏 + 竖屏 |

换音色**不会**把你辛苦生成的配音清空——旧配音标黄提示「需重配」，你点批量配音才替换。
同理，改文案也让该段配音标黄（念的还是旧文字）。两处都是**有意为之**：配音是算出来的
产物，静默丢弃找不回来；自动重配又会在「只想试听一下音色」时白花十几秒。需要换时
点「批量配音」一次配完，或在段卡上单独「重配」。

## 不在改动范围

下面这些是**明确没做**的，不是遗漏。别问「为什么没做」：

| 没做 | 为什么 |
|---|---|
| 字体子集化 | 中文手写字体全字集 3.1MB，子集化要按文案动态生成，收益不抵复杂度 |
| 首屏加载架构改造 | 首次 21.8MB 是模型 + wasm + 字体，加载策略改动大、收益小 |
| 降分辨率 / 降笔数换内存 | 质量优先。抽稀只在「一屏画不完」时按预算抽，不为了省内存砍 |
| 帧率优化到 60fps | 30fps 够用，且逐笔渲染的成本摆在那 |
| 导出耗时硬保证 ≤ 0.6× | 编码速度取决于机器，没有承诺 |
| 场景快照（跳回不重画） | 已知限制，见下 |

## 已知限制

这些是真的限制，不是没做完：

1. **中文声调只区分了二声。** Piper 的中文音素集来自 espeak，espeak 的普通话只用 `ɜ` 后缀标记阳平，一/三/四声在音素层面是一样的。所以配音的声调是靠模型自己从上下文里学的，听起来会有一点"洋腔"。要根治只能换带声调标注的模型，而那个体积远超 10MB。
2. **没有英文音色。** Piper 英文最小档是 60MB（fp16 后 30MB），超出「单语言 <10MB」的线，所以本期只内置中文。文案里的英文单词当前按字母名读，数字按位读（2026 → 二零二六）。
3. **首次打开要下 21.8MB**（模型 10.1MB + wasm 运行时 11.2MB），之后走浏览器缓存。页面有真实字节进度条，也可以点「先跳过语音」直接用手动时长出片。
4. **照片类素材会自动抽稀。** 一张 1280px 的照片管线会给两万多笔，一屏只有两三秒根本画不完、也渲染不动，所以按每笔 0.28ms 的预算均匀抽样。画面会简化，轮廓保留。抽稀按「整块优先」，不丢笔造成白斑。
5. **最多 12 段。** 超过会合并到最后一段。**这是有意设的上限**（已确认保留）：笔触分析
   很吃 CPU，每屏约 22 秒，12 段对应约 5 分半的片子。放宽上限能做长片，但生成时间
   线性增长、长文有把页面搞挂的风险。切段时界面会明确提示合并了多少。
6. **往回拖进度条会从头重画那一屏**（没有做场景快照）。触发条件是「目标早于该屏已画到的位置」——
   同屏内往回跳、跨屏跳、场景标签跳转都会中招。代价随笔数走：实测照片素材（约 2.3 万笔）
   回头跳一次 1～3 秒。只往前拖不受影响：一次 pointermove 只跨十几毫秒，实测 P95 < 200ms
   （`npm run test:perf` 的断言项）。要根治得给每屏存一张快照，内存换时间——本期没做。

## 技术实现

```
js/
  core/
    renderer.js     逐笔渲染：ribbon 填充 + 掩膜裁剪 + 半成品笔尖
    compositor.js   纸面、图卡、字幕合成（1920×1080 / 1080×1920）
    subtitle.js     换行与字号（纯函数）+ 逐字揭示
    timeline.js     多屏时间轴、时长规则、抽稀预算
    exporter.js     WebCodecs 离线编码 → MP4（MediaRecorder 兜底）
    scheduler.js    任务队列：五态、协作式中止、单项重试
  ui/
    dragdrop.js     拖拽绑图（Pointer Events，不用 HTML5 DnD）
    timeline-view.js 底部时间轴
    scene-panel.js  右侧场景设置栏
    undo.js         快照式撤销栈
    queue-panel.js  队列面板
  tts/
    engine.js       onnxruntime 会话、模型加载、合成
    phonemize.js    文本 → 音素 id
  audio/
    wsola.js        变速不变调、重采样、归一化
    mix.js          按时间轴铺音轨
  vendor/           pipeline.js（笔触引擎）、ort、pinyin-pro、mp4-muxer
assets/tts/         模型 + 音素表
```

关键优化（这几条决定了能不能实时播）：

- **掩膜图集**：几乎每一笔都有自己的裁剪掩膜，逐个建 canvas 会让单笔成本到 1.4ms。改成把所有掩膜按货架排进一张 2048² 画布，每个只写一次，单笔降到 **0.15ms**（插画）/ **0.35ms**（照片）。
- **按裁剪段批量绘制**：同一掩膜的连续笔合并成一个 Path2D，按颜色分组，一次 `destination-in`。
- **`targetSec` 只管时长分配，笔数要设 `maxStrokes`** —— 这是踩过的坑。

## 本地跑

```bash
cd inkbrief
python -m http.server 8000
# 打开 http://127.0.0.1:8000
```

纯静态，没有构建步骤。

## 线上部署（GitHub Pages）

<https://longguanhong0755.github.io/inkbrief/>

推 `main` 分支后 Pages 自动构建，约 1 分钟生效。

**首次打开需要下载 21MB**（语音模型 10.1MB + onnxruntime wasm 10.7MB + 字体 3.1MB），
之后走浏览器缓存，第二次打开明显快。

这几个文件都走**分片下载**：切成 1MB 的片、3 路并发、每片最多重试 3 次，下满才收。
这不是优化而是必需——GitHub Pages 在国内只有 50～60 KB/s，一个 10MB 的长连接活不到
200 秒就会被重置（`ERR_CONNECTION_RESET`），整包下载必然失败。分片之后实测线上
**141 秒**完成加载、语音引擎就绪。下载完的内容存进 Cache Storage，服务端不支持
Range 时会自动退回整包下载。

想把速度再提上去，可以把 `assets/tts/` 和 `js/vendor/ort/` 换成国内可达的 CDN
（jsDelivr 实测快 4～6 倍），分片逻辑本身不用改。

**改完 js 记得改版本号。** 入口脚本和模块引用都带 `?v=N`（见 `index.html` 与 `js/main.js`），
Pages 对 `.js` 有 10 分钟缓存，只改内容不改 URL 的话老访客会继续用旧文件。改代码时把
`?v=7` 一起升上去。

## 测试

全部是离线脚本，不依赖人工点网页。

```bash
npm test              # WSOLA 变速不变调（25 项）
npm run test:e2e      # 完整流程 + 导出 MP4（24 项）
npm run test:edge     # 竖屏、空输入、非图片、超段、390px（16 项）
npm run test:perf     # 性能断言（6 项：拖进度条 P95 / 生成预算 / 单笔 / 固定开销 / 抽稀丢块 / 渲染器可寻址）
npm run test:smoke    # 打开页面等语音引擎就绪并试合成（可加 URL= 指向线上）

# 交互层（都需要本地服务器 + playwright-core）
npm run test:timeline      # 时间轴纯函数（63 项）
npm run test:timelineview  # 时间轴 UI（25 项）
npm run test:scene         # 场景设置栏（36 项）
npm run test:undo          # 撤销/重做（30 项）
npm run test:queue         # 生成队列 + 批量配音（32 项）
npm run test:export        # WebCodecs 离线导出 + 双画幅（23 项）
npm run test:dragdrop      # 拖拽绑图（19 项）
npm run test:interaction   # 交互综合（29 项）
npm run test:tts           # 音标/标点（26 项）
npm run test:decimate      # 抽稀策略（39 项）
npm run test:scheduler     # 任务队列纯逻辑（41 项，不用浏览器）
```

跑浏览器测试时用 `URL=` 指向本地服务器，例如：

```bash
URL=http://127.0.0.1:8743 npm run test:e2e
```

`test:perf` 会把四类 seek 都打出来，只有「拖进度条」那一类参与断言——
其余三类要么触发无快照重画、要么是点场景标签那种大跨步，慢是设计使然，
数字留着是为了知道回头跳到底有多贵。照片素材（2.3 万笔）实测：

| 操作 | P50 | P95 |
| --- | --- | --- |
| 拖进度条（每步 16ms） | 26ms | 38ms |
| 大跨步向前（每步 1/30 屏） | 179ms | 284ms |
| 同屏往回跳（重画本屏） | 2.5s | 5.0s |
| 跨屏跳（重画目标屏） | 1.8s | 2.6s |

重建音素表（需要 `@echogarden/espeak-ng-emscripten`，仅开发期）：

```bash
npm run tts:chars && npm run tts:phonemes && npm run tts:table
```
